**Estimated Time:** 10–15 minutes

This is the simplest method in our project, but it's an excellent example of **Encapsulation**.

# Goal

Allow the user to view their current balance without allowing them to modify it.

---

# Method

```python
def check_balance(self):
    print(f"Current Balance : {self.__balance}")
```

---

# Why Use a Method?

Someone might ask:

> Why not just do this?

```python
print(atm.__balance)
```

Because:

```python
__balance
```

is **private**.

Trying to access it directly:

```python
atm.__balance
```

will raise

```text
AttributeError
```

---

# Correct Way

```python
atm.check_balance()
```

Output

```text
Current Balance : 5000
```

---

# Why Not Return Instead of Print?

Good question.

There are two approaches.

---

## Option 1

```python
def check_balance(self):
    print(self.__balance)
```

Simple.

Good for beginners.

---

## Option 2 (Preferred)

```python
def check_balance(self):
    return self.__balance
```

Now

```python
print(atm.check_balance())
```

or

```python
balance = atm.check_balance()
```

or

```python
if atm.check_balance() < 1000:
    print("Low Balance")
```

Returning values makes methods reusable.

---

# Which One Should We Use?

Since this project is moving toward **professional coding practices**, we'll use **Option 2**.

### Final Version

```python
def check_balance(self):
    return self.__balance
```

Then, whenever we need to display it:

```python
print(f"Current Balance : {atm.check_balance()}")
```

### Why is this better?

Because the method has a **single responsibility**:

* `check_balance()` → provides the balance.
* `print()` → handles displaying it.

Separating these responsibilities makes the code more flexible and easier to test.

---

# Updated ATM Class

```python
class ATM:

    def __init__(self):
        self.__balance = 5000

    def deposit(self, amount):

        if amount <= 0:
            raise InvalidAmountError(
                "Amount must be greater than zero."
            )

        self.__balance += amount

        print("Deposit Successful")

    def withdraw(self, amount):

        if amount <= 0:
            raise InvalidAmountError(
                "Amount must be greater than zero."
            )

        if amount > self.__balance:
            raise InsufficientBalanceError(
                "Insufficient Balance."
            )

        self.__balance -= amount

        print("Withdrawal Successful")

    def check_balance(self):
        return self.__balance
```

---

# Testing

# Interview Question ⭐

## Q1

**Why is returning the balance better than printing it inside the method?**

**Answer:**

Returning a value makes the method reusable. The caller can print it, compare it, store it, or use it in calculations. Printing inside the method limits its usefulness and mixes business logic with presentation.

# Step 6 – Menu System

Now we'll build the **interactive ATM menu**, where users can repeatedly choose operations until they exit.

---

# Goal

Display this menu repeatedly:

```text
========================
        ATM MENU
========================

1. Check Balance
2. Deposit
3. Withdraw
4. Exit
```

The menu should continue running until the user chooses **Exit**.

---

# Why Use a Loop?

If we don't use a loop:

```python
print(menu)

choice = input()
```

The menu appears only once.

We want the ATM to stay active until the user decides to leave.

So we'll use:

```python
while True:
```

---

# Basic Menu Structure

```python
while True:

    print("\n===== ATM MENU =====")
    print("1. Check Balance")
    print("2. Deposit")
    print("3. Withdraw")
    print("4. Exit")

    choice = int(input("Enter your choice: "))
```

This displays the menu repeatedly.

---

# Handling Choices

We'll use `if-elif`:

```python
if choice == 1:
    print(f"Current Balance : {atm.check_balance()}")

elif choice == 2:
    # Deposit

elif choice == 3:
    # Withdraw

elif choice == 4:
    print("Thank you for using ATM.")
    break
```

---

# Invalid Menu Choice

Suppose the user enters:

```text
9
```

Instead of just printing:

```text
Invalid Choice
```

We'll use the custom exception we created.

```python
raise InvalidChoiceError("Invalid menu choice.")
```

This keeps our error handling consistent across the application.

---

# Interview Question ⭐

**Why do we use `while True` with `break` instead of asking the user once?**

**Answer:**

Because an ATM is an interactive application. It should continue serving the user until they explicitly choose to exit. The `break` statement provides a clear and controlled way to terminate the loop.
